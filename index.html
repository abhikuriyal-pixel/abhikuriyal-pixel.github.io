Development

DocFoo project

Explore DocFoo / GitHub

DocFoo is a fast, vectorless and non-agentic retrieval engine. It is designed to be a reliable partner for knowledge workers like researchers, medical practitioners, technicians etc. It keeps answers confined to the sources and much more fast & trustworthy (by design) than unrestricted agentic search. The evidence retrieval is super fast with figures, tables, code, citations preserved and no loss of information.

When used with GPT-6 Luna, DocFoo has 58.7% lower query time (8.81 s vs 21.32 s), 80% fewer LLM requests, and 60.1% fewer total tokens than agentic search. It is also 59.4% cheaper than agentic search excluding prompt-caching. See benchmark.

DocFoo integrations

Integration with PiKins

The easiest way to work with DocFoo. Import and index your documents in PiKins, then chat with DocFoo like a teammate. Other teammates can ping DocFoo in a workflow to keep information grounded in sources.

Integration with Hermes

Already using Hermes? Set up the DocFoo plugin once, then start your document questions with dfq in Slack or another connected chat. Hermes delivers the answer directly without rewriting it.

Integration with Coding agents

Supercharge your coding agents with DocFoo. Use the docfoo skill to instruct agents on how to index and query the documents along with other functionalities it offers.

PiKins

Explore PiKins / GitHub

PiKins is an open-source, collaborative multi-agent platform where each agent has its own model, long term memory, and workspace. Think of it as a team of AI teammates you can ping, personalize, and delegate work to. Specifically designed for knowledge workers in technical fields where information reliability is critical.

Model ports for llama.cpp

I’m implementing some niche architectures in llama.cpp, a lightweight C/C++ inference engine for local models. Its flexible low-bit quantization, optimized native kernels, and lean runtime make it a strong alternative to ONNX Runtime for memory-constrained CPU/GPU edge deployments.

llama.cpp model ports

llama.cpp port FalconOCR

FalconOCR is TII’s compact OCR model, processing image patches and text in a single Transformer. I ported it to llama.cpp and wrote custom FalconOCR-specific ggml operators that fuse multi-operation chains into single parallelized CPU kernels.

Approximately 150% faster decode throughput (2.5×) on CPU than the official HuggingFace Transformers implementation running entirely on GPU in my comparison. Image-and-prompt prefill reaches ~500 tokens/s on the same CPU. No CUDA, no Python runtime, no Triton.

Research

CoDEx: Combining Domain Expertise for Spatial Generalization in Satellite Image Analysis

Abhishek Kuriyal, Elliot Vincent, Mathieu Aubry, Loïc Landrieu

EarthVision 2025 - CVPR Workshop

We propose a framework that combines domain-specific experts for satellite imagery from unseen regions. We learn which experts should agree and how to blend their predictions, improving spatial generalization across four datasets.

pCTFusion: Point Convolution-Transformer Fusion with Semantic Aware Loss for Outdoor LiDAR Point Cloud Segmentation

Abhishek Kuriyal, Vaibhav Kumar, Bharat Lohani

SN Computer Science (Springer Nature), 2024

pCTFusion is an architecture combining 3D convolutions with local and global self-attention for outdoor LiDAR segmentation. We also introduce Pointwise Geometric Anisotropy loss to emphasize semantic boundaries and improve performance on SemanticKITTI.

pGS-CAM: Interpretable LiDAR Point Cloud Semantic Segmentation via Gradient-Based Localization

Abhishek Kuriyal, Vaibhav Kumar

ICLR 2023 (Tiny Papers Track)

We introduce a gradient-based method that produces per-point heatmaps at intermediate layers of LiDAR segmentation networks. Using RandLA-Net on SemanticKITTI, we show how these maps help interpret the features behind class predictions.

Evaluating the Impact of Point Cloud Density on Tree Extraction Using Virtual LiDAR in Boreal Forest

Abhishek Kuriyal

Master’s thesis, IISER Bhopal, 2024

We propose a pipeline that detects individual trees in airborne LiDAR using treetop-guided proposals and a Sparse Transformer to predict 3D bounding boxes. Using HELIOS++ forest simulations, we study the effect of point density and compare this approach with sliding-window proposals.
